# Discovery core 0.3.2

An unavailable selected network can now be a recoverable lifecycle state instead of a startup failure. Applications opt in with `waitForNetwork: true`; strict startup remains the default.

- Expose `stopped`, `waiting`, `discovering`, and `error` status with transition events.
- Retry missing interfaces and transient network failures without repeated error events, including failures during socket binding.
- Invalidate stale candidates and ignore late packets from replaced sockets.
- Cancel pending startup and rebind work on stop; allow a clean subsequent start.
- Keep explicit interface addresses pinned. Invalid configuration and permission failures remain errors.

Validation: 20 automated tests and reproducible archive/isolated installation checks. The same runtime code was exercised through the Harness plugin stability candidate on a physical Apple Silicon Mac: Wi-Fi loss with Ethernet failover, restored discovery, service withdrawal/reannouncement, and explicit reconnection over real mDNS/HTTPS.

Download `llm-discovery-discovery-core-0.3.2.tgz` and `SHA256SUMS`. Requires Node.js 22+. This is a developer SDK; npm installs its registry dependencies. Ordinary Harness users only need the bundled plugin package.

中文：新增可选的等待网络模式。网卡暂时消失时保持等待并自动重试，网络恢复后继续发现；不会自动切换到另一张网卡，也不会绕过配置、权限或服务信任校验。
